# クイックコードレビュー

直近の変更を自動レビューし、問題があれば修正する。

## レビュー対象の決定

```bash
# 未コミット変更がある場合
git diff --stat

# 未コミット変更がない場合は直近コミット
git show HEAD --stat
```

## チェック項目

### 1. 構文・ビルドエラー
```bash
npm run build 2>&1 | tail -20
```
- TypeScriptエラー
- orphanedコード（不完全な編集の残骸）

### 2. 用語統一
変更ファイルのみを対象に用語チェック:
- ユーザー向けテキストに「サービス」「インストラクター」「クリエイター」「レッスン」「講師」が残っていないか
- 正しい表現: 「商品」「出品者」「出品」

### 3. セキュリティ
- `console.log` が本番コードに残っていないか（catchブロック内の `console.error` は許可）
- 認証チェック漏れ（APIルートに `getUser()` / `requireAdmin()` がないか）
- authId と Prisma User ID の混同（`user.id` を直接DBクエリに使っていないか）
- SQL/XSSインジェクションの可能性
- ハードコードされた秘密情報

### 4. 型安全性
- `any` 型の使用箇所（新規追加分のみ）
- 型アサーション（`as any`）の使用

### 5. エラーハンドリング
- 空の catch ブロック（`catch (err) {}`）
- `alert()` / `confirm()` の使用（モーダルが望ましい）
- fetch のレスポンスステータスチェック漏れ

### 6. バリデーション
- フォーム入力の負数チェック
- 必須フィールドのバリデーション
- `type="number"` の使用（`type="text" inputMode="numeric"` + handleNumericInput を使うべき）

## レビュー結果フォーマット

```
## レビュー結果

### 重大（修正必須）
- なし / ファイル:行 - 問題の説明

### 改善推奨
- なし / ファイル:行 - 改善の説明

### 良い点
- 変更の良い点を1-2個挙げる
```

## 自動修正
重大な問題がある場合はユーザーに報告後、修正→ビルド確認→コミットまで自動で行う。
